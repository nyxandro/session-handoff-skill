**Скилл для Claude Code, который передаёт незаконченную работу в новую сессию ИИ-агента одним документом, сверенным с настоящим репозиторием.**

Session Handoff это скилл для Claude Code, Codex, OpenCode, Cursor и других агентов, которые
понимают Agent Skills. Когда в сессии кончается контекст или он сжимается, агент пишет один
документ, готовый для копирования в следующую сессию. Агент в новой сессии сверяет его с
репозиторием, прежде чем что-то делать.

## Зачем

Попросите агента "написать промпт для новой сессии", и каждый раз получится что-то своё.

- Один раз пропадёт состояние ветки.
- В другой раз потеряются ваши запреты.
- В третий раз объём задачи незаметно поменяется.

Скилл закрепляет структуру документа, берёт факты о репозитории из скрипта, а не из памяти
агента, и учит принимающего агента проверять документ, а не верить ему.

## Установка

| Агент | Команда |
|---|---|
| Claude Code, как плагин | `/plugin install session-handoff --marketplace nyxandro/skills` |
| Claude Code, Codex, OpenCode, Cursor и другие | `npx skills add nyxandro/session-handoff-skill` |
| Любой агент, вручную | Скачайте [архив `.skill` последнего выпуска](https://github.com/nyxandro/session-handoff-skill/releases/latest/download/session-handoff.skill) и распакуйте в папку скиллов агента |

Выберите один способ. Если поставить двумя, Claude Code загрузит скилл дважды.

<details>
<summary>Требования и другие способы установки</summary>

<br>

- Скрипту нужен `git`. `gh` не обязателен и нужен только для списка открытых pull request.
  Скрипт только читает и никогда не обращается к удалённому репозиторию.
- Установка плагина одной командой работает в Claude Code 2.1.275 и новее. На старой версии
  сначала добавьте каталог командой `/plugin marketplace add nyxandro/skills`, потом выполните
  `/plugin install session-handoff@nyxandro`.
- Версия в каталоге не закреплена, поэтому каждый коммит сюда приходит пользователям плагина как
  обновление. Выполните `claude plugin marketplace update nyxandro` и
  `claude plugin update session-handoff@nyxandro` или включите автообновление в
  `/plugin` → Marketplaces.
- С `npx skills` добавьте `-g`, чтобы скилл стоял во всех проектах. Чтобы поставить определённую
  версию, допишите её метку, например `nyxandro/session-handoff-skill@v1.0.0`.
- Можно и клонировать репозиторий, а в папку скиллов агента положить ссылку на папку
  `session-handoff/`. Сборка не нужна.

</details>

## Как пользоваться

**В конце сессии** попросите передачу.

- *Напиши промпт для новой сессии, я скопирую и отправлю агенту.*
- *У тебя скоро кончится контекст. Запиши все детали для следующей сессии.*
- *Сделай передачу, следующая сессия про сбои в дайджесте.*

Агент запускает `scripts/repo-state.sh`, собирает из сессии решения, запреты и доказательства и
отдаёт в чат один блок, готовый для копирования. Файлов он не создаёт, если вы не попросите.

**В начале новой сессии** вставьте блок и скажите "вот контекст" или "продолжаем". Дальше агент
делает пять вещей.

1. Читает документ до конца.
2. Запускает тот же скрипт и первым делом называет все расхождения с настоящим репозиторием.
   Ветка, HEAD, незакоммиченные и неотправленные изменения, открытые pull request.
3. Проверяет, что каждый упомянутый файл существует, и читает те, что помечены "прочитать
   первым".
4. Докладывает в пяти-семи строках. Где мы, что сделано, что первое в очереди, что решать вам.
5. Останавливается. Работа начинается только по вашему слову.

## Что в документе

| Раздел | Что туда идёт |
|---|---|
| Суть в пяти строках | Что за работа, где остановились, на чём сосредоточиться в следующей сессии |
| Состояние проекта и репозитория | Папка, ветка, HEAD, незакоммиченные и неотправленные изменения, открытые PR, чужие правки с пометкой "не трогать" |
| С чего началось | Исходная проблема с фактами и датами, вашими словами |
| Сделано, не переделывать | Каждый пункт с проверяемым доказательством, например SHA коммита, тест или PR. Недоказанное идёт в раздел "Предполагается, проверить" |
| С чего начать и почему | Первый шаг следующей сессии и почему он первый |
| Прочитать первым | Пути к файлам с кодами и статусами пунктов, а не пересказ |
| Как работать | Порядок работы, который вы требуете в этой задаче |
| Ограничения окружения | Только те, что касаются задачи |
| Запреты в этой задаче | Вашими словами, близко к цитате |
| Скиллы для следующего агента | Какие скиллы нужны задаче и зачем |

Документ пишется на том языке, на котором вы говорите с агентом. Жёсткий потолок 500 строк, и
это потолок, а не цель. Секреты, пересказ кода, логи, трассировки и копии того, что уже лежит в
репозитории, туда не попадают.

## Пример

Настоящий вывод `scripts/repo-state.sh` в одном из наших репозиториев, сокращённый.

```text
Folder: ~/projects/feature-blueprint-skill
Branch: main
HEAD: 726b268 2026-11-06 Russian README in the new layout; changelog without em dashes
Upstream: origin/main (unpushed commits: 0, not pulled: 0; as of last fetch)
Working tree: clean
Stash entries: 0
Last commits (5):
  726b268 2026-11-06 nyxandro: Russian README in the new layout; changelog without em dashes
  d2ac941 2026-11-06 nyxandro: README: rewrite the English page, install table first, ...
Open PRs from this branch: none
```

Эти же строки попадают в документ передачи, а принимающий агент сравнивает их с тем, что видит
сам.

## Версии

Текущая версия записана в поле `metadata.version` файла `session-handoff/SKILL.md`, так что
любая установленная копия показывает, какая она. У каждой версии есть метка в git и
[выпуск](https://github.com/nyxandro/session-handoff-skill/releases) со своим архивом.
[CHANGELOG.md](CHANGELOG.md) рассказывает, что изменилось.

<details>
<summary>Устройство репозитория</summary>

<br>

```text
session-handoff/              сам скилл
  SKILL.md                    инструкции для обеих сторон и шаблон документа
  scripts/repo-state.sh       состояние репозитория одной командой, только чтение
dist/session-handoff.skill    папка скилла архивом для скачивания
CHANGELOG.md                  что изменилось в каждой версии
README.md, README.ru.md       эта страница на английском и на русском
```

</details>
